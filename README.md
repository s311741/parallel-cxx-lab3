# A.3. Стандартные потоки II

## Описание задачи

Реализовать интерактивную программу, описанную в предыдущей лабораторной работе, но расчеты необходимо проводить в основном процессе с использованием пула потоков. У пользователей должна быть возможность вводить команды, пока проводятся другие расчеты. Программа должна быть выполнена в виде 1 исполняемого файла, принимающая в качестве аргумента командной строки следующие параметры:

```
$ ./lab <threads> [seed]
```

Параметр `threads` определяет количество потоков в пуле потоков. Опциональный параметр `seed` должен использоваться для генератора псевдослучайных чисел, генерирующего зерна для каждого потока в пуле. Считать параметр равным 0, если он не задан.

Помимо создания наборов фигур, для проведения расчетов и управления пулом потоков должны быть поддержаны следующие команды:
- `shutdown`\
  Ожидание выполнения всех расчетов и остановка пула потоков. Команда считается ошибочной, если пул уже остановлен.
- `area-pool <calc-name> <set-name> <tasks> <tasks-tries>`\
  Запуск расчета с именем calc-name для указанного набора `set-name` с созданием `tasks` заданий, в каждом из которых будет `tasks-tries` испытаний метода Монте-Карло. Команда считается ошибочной, если расчет с указанным именем уже создавался.
- `status <calc-name>`\
  Проверка статуса завершения расчета с именем `calc-name`. Если расчет завершен, то должно быть выведено через пробел время расчета в милисекундах и расчитанная площадь. Значения выводятся с точностью до трех знаков после запятой. Если расчет не завершен, то должно выводиться сообщение `<IN PROGRESS>`. Команда считается ошибочной, если расчет с указанным именем не создавался.

## Работа с проектом

Конфигурация, сборка и запуск отладочной сборки:
```
cmake --preset debug
cmake --build --preset debug
./build/debug/thread-pool
```

## Загрузка работы

1. Выполненную работу в своем форке нужно загрузить в отдельную ветку.
2. Создать PR в свой `master` и запросить ревью у всех ревьюверов.
3. После проверки, если требуется, ответить на комментариии и поправить код.
4. Работа считается сданной когда все комментарии закрыты и PR заливается в основную ветку `master`.

В проекте рекомендуется использование гайдлайна по форматированию кода из `coding-guidelines.pdf`.

## Использование clang-format

### Применение форматирования

Находясь в корне репозитория (где лежит `.clang-format`), выполните:

```bash
clang-format -i $(find . -name "*.cpp" -o -name "*.h")
```

Команда отформатирует все исходные файлы проекта на месте (`-i` — in-place).

### Проверка без изменения файлов

Чтобы просто проверить соответствие без перезаписи:

```bash
clang-format --dry-run --Werror $(find . -name "*.cpp" -o -name "*.h")
```
